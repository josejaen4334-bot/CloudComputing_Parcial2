Modelos de servicio

IaaS, PaaS y SaaS: quién administra qué

Cada modelo reparte las responsabilidades de manera distinta entre tú y el proveedor. Elegir bien ahorra tiempo y dinero.

  • Resumen
  • Los tres modelos
  • Serverless
  • Comparativa

Tres capas, tres niveles de control

La nube ofrece tres modelos principales según el nivel de control que necesites:

La analogía de la pizza. IaaS es comprar la masa y cocinarla en un horno prestado; PaaS es pedir la pizza para recoger y poner tú la mesa; SaaS es cenar en el restaurante: solo disfrutas.

Los tres modelos principales

Bajo nivel

IaaS

Infraestructura como Servicio

Proporciona los bloques fundamentales de TI. Otorga acceso a recursos de red, computadoras (virtuales o dedicadas) y espacio de almacenamiento.

  • Control: alto sobre la infraestructura.
  • Ejemplos: AWS EC2, Google Compute Engine, Azure Virtual Machines.
Nivel intermedio

PaaS

Plataforma como Servicio

Elimina la necesidad de gestionar la infraestructura subyacente (servidores, sistema operativo) para centrarse únicamente en la implementación y gestión de aplicaciones.

  • Control: medio (enfocado en el código).
  • Ejemplos: Heroku, AWS Elastic Beanstalk, Google App Engine.
Nivel usuario

SaaS

Software como Servicio

Proporciona un producto completo ejecutado y gestionado por el proveedor del servicio. El usuario no se ocupa del mantenimiento del software.

  • Control: bajo (solo configuración).
  • Ejemplos: Google Workspace, Microsoft 365, Salesforce.

Un modelo emergente: serverless (FaaS)

En las funciones como servicio (FaaS) escribes una pequeña función y el proveedor la ejecuta solo cuando ocurre un evento (una petición web, un archivo subido, un mensaje). No administras servidores, la capacidad se ajusta sola y pagas únicamente por el tiempo de ejecución. Ejemplos: AWS Lambda, Azure Functions y Google Cloud Functions.
